# مصفوفة متطلبات وقبول Mirror Scorpion v4

> **الغرض.** هذه الوثيقة هي مصدر العمل الحاكم لتجنب فقدان أي نقطة من الوصف. لا تعدّ الميزة مكتملة لأن لها واجهة فقط؛ بل يجب أن تجتاز معيار القبول المحدد على APK وجهاز Android عند الحاجة. راجعت هذه المصفوفة الوصف المرجعي، مواصفة الواجهة، سجل الاختبارات الفعلية، والتدقيق التقني الحالي. [1] [2] [3]

## 1. قواعد التنفيذ والشفافية

| القاعدة | القرار التنفيذي |
|---|---|
| المنصة | الفرع النشط Flutter/Android فقط. لا يُنشأ مشروع Expo أو تطبيق بديل. |
| البناء | لا تنتقل أي دفعة إلى التالية قبل نجاح `flutter analyze` و`flutter test` وAPK في GitHub Actions. |
| قبول الهاتف | ما يتطلب ميكروفوناً أو كاميرا أو Overlay أو جودة نص حقيقية لا يعتبر مقبولاً قبل اختبار Android. |
| الصدق الوظيفي | تعرض الواجهة نجاحاً أو خطأً حقيقياً فقط؛ لا نستخدم نصوصاً مثل «ترجمة: النص» أو ملفاً صوتياً/فيديو وهمياً. |
| الأمن | لا مفاتيح API أو مفاتيح RSA خاصة أو JSON لحساب خدمة داخل APK أو المستودع أو الرسائل. |
| PRO | يبقى مفتوحاً كواجهة غير مُقيِّدة إلى أن تنجح الخدمة المعنية على Android، ثم يصبح القفل خادمياً فقط. |
| الخصوصية | لا Accessibility ولا Notification Listener ولا قراءة تلقائية لرسائل WhatsApp أو البريد. كل نص للفقاعة يمر عبر مشاركة أو اختيار صريح من المستخدم. |

## 2. مبدأ المساحة داخل الكروت

المساحة داخل كروت العمل يجب أن تخدم النص أو الصورة أو اللعبة، لا الشرح الطويل. تبقى تسمية قصيرة وحالة تنفيذ أو خطأ قابلة للفهم داخل الكرت، بينما تنتقل الحدود التقنية والتفاصيل التعليمية إلى صفحة «حول التطبيق والمساعدة» ووثيقة الدعم.

| الكرت | التعديل المطلوب في المساحة | معيار القبول المرئي |
|---|---|---|
| الترجمة النصية | إزالة فقرة الشرح الطويلة من أسفل المحررين، وتكبير كل محرر وإتاحة تمرير النص داخله. | يظهر نص متعدد الأسطر بوضوح مع الميكروفون والدبوس دون حجب آخر سطر. |
| الحوار | تقليل الوصف العلوي إلى سطر واحد، وتكبير محرري المصدر والنتيجة. | يظل شريط التحكم مرئياً، ويظهر حوار طويل قابل للتحرير/النسخ. |
| العدسة والمستندات | الاحتفاظ بحالة مسح قصيرة فقط، وتخصيص أغلب الارتفاع لمعاينة الأصل والنص/الترجمة. | لا تتزاحم أزرار الكاميرا والملف والنص المستخرج. |
| القصص والإلهام | استبدال الشرح الثابت بعنوان وقسم/مصدر، وتخصيص المساحة للقارئ وقصة المستخدم. | عنوان القصة، المصدر، والنص المقروء أولى من الشرح. |
| الألعاب | إخفاء الشرح الطويل خلف زر معلومات، وإعطاء اللوحة أكبر مساحة ممكنة. | تظهر رقعة الشطرنج وقطعها كاملة قابلة للمس على الهاتف. |
| الإعدادات | استخدام عناوين أقسام قصيرة وصفحات فرعية للحزم والخصوصية وPRO. | لا تحجب النصوص القائمة أو أزرار التنزيل والتفعيل. |

| المتطلب | التنفيذ/الحالة الصادقة | قبول APK المطلوب | الحد أو الخطوة التالية |

| منع التعريب المضلل | منفذ واجتاز قبول Android مختصراً | لا تمرر «جود نايت» إلى مترجم الإنجليزية كناتج إنجليزي. | إن لم تثبّت لغة الجهاز في خدمة التعرف تظهر رسالة واضحة. |

| الترجمة النصية | ML Kit محلي مع تنزيل نماذج وتقدم | زوج مدعوم يترجم بعد تنزيل أولي ثم أسرع لاحقاً. | ML Kit ليس قائمة 100 لغة كاملة ولا يضمن كل زوج مباشر. |
| التحرير والترجمة الآلية | منفذ | تعديل النص العلوي يحدث الترجمة بعد تأخير قصير قابل للملاحظة. | لا ترجمة إذا كان النص فارغاً أو فشل النموذج. |
| TTS | صوت النظام فقط | تشغيل/إيقاف النص الناتج بلغة الهدف المتاحة. | أصوات Seif/Salma/Sama/Sara ونسخ الصوت ليست مفعلة. |
| اختيار ملف صوت | اختيار محلي فقط | يعرض اسم الملف ولا يدّعي تفريغه أو ترجمته. | يتطلب Google STT/Storage/Functions وفوترة وموافقة قبل التفعيل. |
| نسخ ومشاركة | النسخ للنص متاح؛ مشاركة صوت مترجم ليست مكتملة | لا يظهر «مشاركة ملف صوت» كأنه موجود دون توليد صوت فعلي. | يحتاج TTS قابل للتصدير وتوقيع ملف حقيقي. |

## 14. ترتيب التنفيذ القادم

1. **محتوى موثوق:** اعتماد schema لحزم المحتوى يشمل `packageId/version/hash/license/sourceCitation`، والتحقق عند الاستيراد وزر حذف قبل إضافة محتوى ديني واسع.
2. **قبول Android المتبقي:** توثيق اختبار لغة نظام غير عربية بالاسم، ثم OCR لاتيني وTTS على جهاز فعلي.
3. **عقد خدمة واحد في كل مرة:** قبل PDF أو تفريغ الصوت أو LLM، حدد المزود والتكلفة والاحتفاظ والحذف وrequest/response وحالات الإلغاء والفشل.
4. **فصل توافق الفقاعة/الألعاب:** نموذج Android-native للفقاعة ونموذج 3D منعزل، مع APK مستقل لكل تجربة قبل دمج أي مكتبات.
5. **الدفع وPRO أخيراً:** Play Billing وbackend entitlement ووقت خادم وSandbox وإلغاء/استعادة قبل أي قفل فعلي.
