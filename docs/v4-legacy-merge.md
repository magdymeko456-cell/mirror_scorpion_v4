# خطة الدمج بين النسخة الناجحة v2 وتحديثات v3 في v4

## القرار المعماري

نسخة v4 تعتمد Expo/React Native، لذلك لا يتم نسخ كود Dart أو ملفات Flutter من v2. يتم نقل السلوك الناجح والهوية البصرية والبيانات المحلية فقط، ثم إعادة تنفيذها بمكونات React Native وخدمات Expo الحالية.

| مجال الدمج | المصدر الناجح في v2 | التنفيذ في v4 | الحالة |
|---|---|---|---|
| الهوية البصرية | خلفية وشعار العقرب المعدني الأزرق | `legacy-scorpion-hero.jpeg` داخل Hero، مع إبقاء أيقونة launcher مربعة مستقلة | منقول |
| الشاشة الرئيسية | ترتيب الكروت الستة، مفتاح الفقاعة، التدرج الكحلي | كروت v4 العمودية، ألوان Royal Dark، صورة Hero، والتنقل بـ Expo Router | مدمج |
| الترجمة النصية | 100 لغة، مايك، نطق، نسخ ومشاركة ومسح | مسار v4 الآلي، TTS، Clipboard، رفع الصوت والتفريغ، مع نفس ترتيب الوظائف | مدمج |
| الحوار | تبديل اللغات، سجل محادثة، نطق الترجمة | DialoguePanel الحديث مع الترجمة والتسجيل وTTS | مدمج |
| المستندات | OCR، حد الصفحات، عرض الأصلي والترجمة، توقيع مائل | OCR متعدد الوسائط عبر الخادم، عرض مزدوج وتنزيل المصادر | مدمج وموسع |
| القصص والإلهام | قصص الأنبياء والأحاديث والبيانات المحلية | JSON محلي أوف لاين + فهرس خارجي منسوب + LLM برسائل وسيناريو فيديو آمن | مدمج وموسع |
| الألعاب | شطرنج وروبيك | ChessBoard ومحرك قانوني ومؤقت ومكعب تفاعلي في v4 | مدمج وموسع |
| الإعدادات | الوضع الداكن، الأصوات، PRO، معلومات التطبيق | إعدادات v4 مع حزم لغات، مصادر قصص، فقاعة Native، وPRO | مدمج وموسع |
| الفقاعة | System Overlay في v2 | Android Foreground Overlay Service قابلة للسحب، Share/Process Text، دون قراءة تلقائية للتطبيقات | مدمج مع اختبار جهاز مطلوب |

## المحتوى الأوف لاين المنقول

تمت إضافة ملفات `hadith_qudsi.json` و`hadiths.json` و`quran_stories.json` و`stories.json` إلى `assets/data/`. ويحوّل `lib/legacy-content.ts` البيانات إلى عناصر مشتركة تعرضها `StoriesPanel` مع اسم المصدر، وتعمل دون اتصال بالشبكة. تبقى المصادر البعيدة خياراً مكملاً وليست شرطاً لعرض المادة المحلية.

## ما لم يُنقل عمداً

لم تُنقل خدمات Flutter أو حزم ML Kit أو واجهات الدفع القديمة أو أساليب التشفير غير الموثقة. الدفع الرقمي داخل تطبيقات المتاجر يحتاج مساراً مناسباً لسياسة Apple وGoogle، والـ MP4 الحقيقي والنسخ الصوتي يتطلبان مزودين واضحين، أما أدوات v4 الحالية فتظل منفصلة وقابلة للاختبار.

## معيار القبول

تُقبل عملية الدمج عندما يمر `pnpm check` و`pnpm test` و`pnpm lint`، ويمر تحليل YAML وBash للملفات التنفيذية، ثم يُبنى APK من GitHub Actions. ولا تُعتبر الفقاعة الأصلية مكتملة ميدانياً قبل اختبارها على Android فعلي مع صلاحية الظهور فوق التطبيقات وShare وProcess Text.
