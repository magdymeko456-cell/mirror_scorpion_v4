# تصميم فهرس مصادر GitHub v1

## القرار

سيبدأ المشروع بفهرس داخل المستودع العام الحالي `magdymeko456-cell/mirror_scorpion_v4` تحت `content_catalog/`. هذا يحقق رابطاً واحداً واضحاً وسريعاً من دون حساب مستخدم أو خادم جديد، ويحصر البيانات المتاحة في حزم صغيرة مرتبة يمكن للمستخدم اختيارها واحدةً واحدة. يبقى الانتقال إلى مستودع محتوى مستقل لاحقاً ممكناً من دون تغيير صيغة الحزمة.

## مسار المستخدم

1. يعرض التطبيق قائمة الفهرس: الاسم، الفئة، اللغة، الحجم التقريبي، المصدر، الترخيص، والإصدار.
2. يضغط المستخدم «تنزيل» لحزمة محددة؛ لا يوجد تنزيل خلفي أو تنزيل شامل.
3. يجلب التطبيق **الفهرس المتجدد** من `main`، ثم ملف الحزمة من GitHub Raw عند وسم محتوى محدد، ثم يحسب SHA-256 للبايتات الخام.
4. يرفض التطبيق الملف إن خالف الهاش أو البنية أو الإصدار المقبول، ولا يستبدل إصداراً أحدث بإصدار أقدم.
5. بعد نجاح التحقق، يحفظه التطبيق كتابةً ذرية في مساحة التطبيق ويعرض المصدر والترخيص مع زر حذف صريح.

## فهرس `index.json`

| الحقل | الغرض |
|---|---|
| `catalogVersion` | إصدار بنية الفهرس، وليس إصدار التطبيق. |
| `releaseRef` | وسم Git ثابت مثل `content-v1.0.0` يستعمل لقراءة الحزم، بينما يبقى `index.json` نفسه على `main` لتحديث الأسماء والترتيب والحالات دون تحديث APK. |
| `packages[].order` | ترتيب العرض في التطبيق. |
| `packages[].status` | `available` أو `requires_review` أو `retired`. لا رابط تنزيل للحالة غير المتاحة. |
| `packages[].scope` | النطاق الواضح مثل `inspiration` أو `quran_narratives`. |
| `packages[].sourceCitation` و`license` | بيانات ظاهرة قبل التنزيل ولا تُختصر إلى اسم غير قابل للتحقق. |
| `packages[].contentPath` و`contentSha256` | موضع الحزمة وهاش بايتاتها للتحقق قبل الحفظ. |

## الحدود الأمنية والقانونية

يوفر هاش الحزمة كشف التلف أو عدم تطابق الملف، لكنه لا يثبت وحده هوية ناشر الفهرس إذا عُدّل الفهرس والحزمة معاً من جهة تمتلك صلاحية المستودع. لذلك تعتمد v1 على حوكمة الوصول إلى المستودع ووسم إصدار للمحتوى، وتضيف v2 توقيع فهرس بمفتاح عام مضمّن قبل قبول مصادر خارجية واسعة. لا تضاف حزمة دينية أو منقولة إلا مع إحالة واضحة وحق استخدام ظاهر ومراجعة قبل النشر.

توثق GitHub أن رابط الملف باستخدام معرف التزام يثبت النسخة التي يشير إليها، بينما يتغير رابط الفرع مع تحديثه.[1] لهذا يستعمل تصميم النشر وسم محتوى ثابتاً لكل إصدار، مع إمكان ترقية لاحقة إلى SHA صريح في الفهرس. كما أن Contents API يعرض خام الملف ويذكر أن `download_url` مؤقت، لذلك لا يعتمد التطبيق على URL مؤقت صادر من API؛ بل يبني رابط Raw من `releaseRef` ومسار الحزمة.[2]

## معايير قبول الدفعة البرمجية التالية

| الاختبار | النتيجة المطلوبة |
|---|---|
| فهرس متاح | تظهر حزمة المالك الأصلية باسمها ونطاقها وحقوقها. |
| مصدر غير موثق | يظهر في الفهرس بلا زر تنزيل. |
| تنزيل سليم | يطابق SHA-256، ويحفظ محلياً، ويظهر في القائمة. |
| ملف معدل | يرفض قبل الحفظ ويعرض خطأ نزاهة واضحاً. |
| حذف | يمسح ملف الحزمة والفهرس المحلي بعد تأكيد المستخدم. |
| شبكة غير متاحة | لا يفقد التطبيق الحزم المحفوظة، ويعرض خطأ تحميل واضحاً. |
