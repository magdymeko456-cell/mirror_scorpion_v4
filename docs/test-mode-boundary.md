# وضع الاختبار المحلي والمحاكي

## القرار

يبقى مشروع Mirror Scorpion v4 في **وضع اختبار محلي ومحاكي** في هذه المرحلة. دالة `healthCheck` موجودة ومختبرة عبر المحاكي، لكن لا تُنشر إلى مشروع Firebase الحي حتى يكتمل التطبيق وتعود مرحلة الاختبارات الحية.

| المجال | الحالة الحالية | ما لا يجوز الادعاء به |
|---|---|---|
| Firebase Android | تهيئة `firebase_core` وبناء APK اجتازا CI | لا يثبت ذلك أن دالة حية متاحة على الإنترنت |
| Cloud Functions | هيكل آمن واختبار محاكي لـ`healthCheck` | لا توجد دالة منشورة أو خدمة ترجمة حية |
| ML Kit | مرحلة التنفيذ المحلي التالية | لا يجوز عرض ناتج ترجمة أو OCR مصطنع |
| PRO | واجهة فقط والتحقق الخادمي مؤجل | لا تُقفل أي خدمة وفق اشتراك محلي |

## قاعدة القبول

لا تُطبّق قيود PRO الخادمة إلا بعد نشر الدوال الحية، واختبار ترجمة وصوت وOCR وقصص وفق مصفوفة الاختبارات على جهاز Android فعلي. تظل رسائل الواجهة صادقة: الخدمة غير المتصلة يجب أن تعرض حالة عدم التوفر أو طلب اختبار محلي، لا نتيجة مزيفة.

## العودة إلى النشر

عند اكتمال الخدمات المحلية، يُستأنف النشر بوضوح عبر `firebase deploy --only functions:healthCheck --project mirorr-d11b2` من حساب يملك المشروع. وبعد نجاح الاستجابة الحية تضاف كل دالة بمفردها مع اختبار APK قبل الانتقال إلى قفل PRO.
