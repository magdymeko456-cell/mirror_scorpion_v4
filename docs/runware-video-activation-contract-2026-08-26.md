# عقد تفعيل فيديو Runware

**تاريخ العقد:** 26 أغسطس 2026
**الحالة:** تصميم غير نشط؛ لا مفتاح، لا رصيد، لا حساب إنتاجي، ولا طلب شبكي من التطبيق.

## الهدف

يعتمد Mirror Scorpion على **Runware** كمزود فيديو مرشح لتطبيق منشور. لا يتصل Flutter بـRunware ولا يحتوي APK على مفتاح. لا يبدأ خادم Firebase أي طلب إلا بعد تحقق المصادقة والموافقة والحد المالي. [1] [2]

| الحقل | قاعدة التفعيل المستقبلية |
|---|---|
| نوع المهمة | `videoInference` فقط. [1] |
| المعرّف | ينشئه الخادم UUID v4؛ لا يثق بمعرّف من التطبيق. |
| التسليم | `deliveryMethod: async` مع polling أو webhook للنتيجة. [2] |
| النموذج | يختاره الخادم من قائمة معتمدة بعد مراجعة السعر والرخصة. |
| التكلفة | يطلب الخادم `includeCost: true` ويسجل التكلفة الفعلية؛ لا يعرض التطبيق سعراً ثابتاً. [1] |
| الناتج | MP4 فقط في التجربة الأولى؛ رابط مؤقت ثم تخزين معتمد أو حذف. |
| البيانات | نص القصة المختار فقط؛ لا صور ولا أصوات ولا وجوه ولا بيانات شخصية في المرحلة الأولى. |

## الحالات والإلغاء الصادق

تسجل الوظيفة الحالات `draft` و`awaitingConsent` و`rejected` و`queued` و`processing` و`completed` و`failed` و`cancelRequested` و`discardOnArrival` و`deleted`.

> لا تتعهد الواجهة بإلغاء حوسبة Runware بعد إرسال المهمة؛ توثق المراجع المراجعة التسليم غير المتزامن وpolling وwebhook، لا نقطة إلغاء عامة. لذلك يلغي التطبيق قبل الإرسال، أو يضع `discardOnArrival` بعد الإرسال فلا يعرض الناتج ويزيل مرجعه فور وصوله. [2]

## الخصوصية والاحتفاظ

تذكر وثائق Runware أن مخرجات الروابط تبقى 7 أيام افتراضياً ويمكن ضبط `ttl` في الطلب. ستختبر قيمة TTL قصيرة قبل أي تشغيل عام، ولا يحفظ ملف دائماً إلا بعد اعتماد تخزين مستقل. [1]

يعرض التطبيق قبل الإرسال نص القصة المحدد واسم Runware وحقيقة أن الفيديو مولّد آلياً وصيغة الموافقة وعدم ضمان إلغاء الحوسبة بعد البدء. لا يرسل شيئاً عند غياب الإيصال أو إذا كانت الحصة اليومية أو الشهرية صفراً.

## الحدود الحالية

| البند | الحالة الحالية |
|---|---|
| اشتراك API | لا يوجد؛ Runware PAYG بلا اشتراك أو حد أدنى. [3] |
| ميزانية المالك | 0 حتى اعتماد صريح. |
| حد المستخدم اليومي | 0 حتى اعتماد صريح. |
| فيديو غير محدود | غير متاح؛ كل فيديو له تكلفة وفق النموذج والمدة والدقة. [3] |
| التجديد التلقائي | غير مفعّل. |
| المفتاح | غير موجود في APK أو المستودع. |

## مسار التفعيل اللاحق

يحدد المالك السقف الشهري والحصة اليومية والمدة والدقة والمنطقة والاحتفاظ، ثم يعتمد نموذجاً وسعراً، ويضع `RUNWARE_API_KEY` كسراً خادمياً فقط. بعد نشر Firebase بموافقة مستقلة، ينفذ اختبار مالك واحد بموافقة وسجل تكلفة، ثم يختبر الحذف والفشل والحدود على Android قبل الإتاحة العامة.
