# مراجعة الوصف الدقيق مقابل التنفيذ الفعلي

**المشروع:** Mirror Scorpion v4 — Flutter/Android  
**تاريخ المراجعة:** 24 أغسطس 2026  
**خط الأساس:** الالتزام `8ee42d3`، وتشغيل GitHub Actions `32688675192` ناجح: فحص Functions، التحليل الساكن، اختبارات Flutter، وبناء APK.

> **الخلاصة الصريحة:** التطبيق لم يعد هيكلاً فارغاً. توجد ترجمة محلية، تعرف كلام من خدمة الجهاز مع حارس ضد السقوط الصامت إلى العربية، OCR لاتيني للصور، قارئ محتوى محلي، شطرنج قانوني بساعة وخصم محلي، وإعدادات وخصوصية مبدئية. لكنه **ليس مطابقاً كاملاً للوصف بعد** لأن PDF الحقيقي، تفريغ الملفات الصوتية، الفقاعة فوق التطبيقات، الفيديو المتحدث، الأصوات المميزة ونسخ الصوت، روبيك و3D الحقيقيان، الدفع، وPRO الخادمي لم تُنفذ.

## 1. مقياس الحالة المعتمد

| الرمز | المعنى |
|---|---|
| **مقبول** | نفذ في APK واجتاز اختبار جهاز Android موثقاً. |
| **مبني ويحتاج قبول Android** | اجتاز CI؛ يحتاج ميكروفوناً أو كاميرا أو سلوك هاتف لا يمكن حسمه في CI. |
| **جزئي وصادق** | ينفذ جزءاً حقيقياً ويعرض بوضوح ما لا يفعله. |
| **بوابة خارجية** | يحتاج مزوداً أو فوترة أو موافقة أو حقوق محتوى أو قرار نشر. |
| **غير منفذ** | لا توجد خدمة أو تجربة وظيفية قابلة لقبول المستخدم بعد. |

## 2. الصورة العامة والهوية

هوية **Royal Dark**، شعار العقرب وانعكاسه، والشبكة ذات الكروت الستة موجودة وتحافظ على ترتيب العمل المطلوب. كما تحسنت مساحة محررات الترجمة والحوار لتخدم النص الطويل بدلاً من الشرح الداخلي.

لكن توجد ملاحظة حوكمة مهمة: لوحة البداية لا تزال تعد المستخدم بعبارات أوسع من التنفيذ، مثل «100 لغة + مايك»، و«ألعاب 3D»، و«مكتبة ذكية متكاملة». لا تتوافق هذه التسميات مع حدود ML Kit والألعاب الحالية؛ وهي أعلى أولوية تصحيح في الواجهة لأن الصدق البصري يجب أن يسبق التوسع التقني.

| عنصر الواجهة | الوضع الصحيح حالياً | التعديل المقترح |
|---|---|---|
| «100 لغة + مايك» | الترجمة المحلية تعمل بين أكثر من 50 لغة، مع جودة متغيرة ومعالجة وسيطة عبر الإنجليزية لبعض الأزواج. | «ترجمة محلية + مايك» مع صفحة حزم لغات تشرح النطاق الحقيقي. |
| «مستندات وعدسة — ترجمة صور وملفات» | OCR لاتيني للصور؛ PDF اختيار ملف فقط. | «عدسة OCR وصور» مع وسم PDF بأنه قيد الإعداد. |
| «ألعاب 3D» | الشطرنج القانوني 2D مقبول؛ روبيك و3D غير منفذين. | «ألعاب وتفكير» وداخل الكرت: «شطرنج قانوني» و«روبيك قريباً». |
| «مكتبة ذكية متكاملة» | توجد حزمة أصلية وحزمة اقتباسات يزودها المالك، لا مكتبة دينية واسعة موثقة أو AI حي. | «قصص وإلهام محلي» مع إظهار المصدر لكل حزمة. |

## 4. الفجوات التقنية الحاكمة

### ما يجب أن يبقى خارج APK

لا يدخل مفتاح API أو حساب خدمة أو مفتاح RSA خاص أو منطق إصدار PRO إلى التطبيق. خدمة PRO الحالية تحفظ معرّف تثبيت محلياً وتعيد حالة Premium إلى `false` عند التشغيل؛ لذا هي واجهة تحضير وليست نظام ترخيص. قرار القفل الصحيح يتطلب backend يتحقق من entitlement، وقت خادم، انتهاء/إبطال، وربط جهاز محسوب بعناية.

توصي Google بأن تُدار مهام الدفع والتحقق والاشتراكات وإشعارات تغيّر الحالة من backend آمن، لا من قرار محلي داخل تطبيق Android.[2] [3] ويمكن أن يساعد Play Integrity في تقدير أصالة التطبيق والجهاز، لكنه لا يغني عن تحقق الخادم أو سياسة مقاومة إساءة متعددة الطبقات.[4]

### الصوت وPDF والفيديو ليست «أزراراً»

تفريغ الصوت القصير والطويل وخدمة PDF والفيديو هي أنظمة Jobs. في Speech-to-Text، الملفات الأطول من دقيقة تستخدم batch غير متزامن وتحتاج Cloud Storage، عملية قابلة للاستعلام، فوترة، وتمكين API وأدوار IAM.[5] وتبقى تكلفة الصوت والتخزين والخدمات المرافقة مستقلة وفق الاستخدام.[6] لذلك الترتيب الصحيح هو: **موافقة التكلفة → عقد upload/session/job/status/delete → سياسة احتفاظ → Function → واجهة تقدم وإلغاء → اختبار Android**.

### الفقاعة لا يجوز اختصارها بمكتبة واجهة

على Android الحديث، تفرض الخدمة الأمامية نوعاً وأذونات مناسبة، وتضيق قواعد تشغيلها في الخلفية. كما أن Android 15 يقيّد مسار `SYSTEM_ALERT_WINDOW` ما لم يكن Overlay مرئياً بالفعل.[7] [8] لهذا يجب أن تبنى الفقاعة كـnative module مستقل، وبـShare/Process Text واختيار المستخدم فقط، من دون Accessibility أو Notification Listener أو قراءة الرسائل.

## 6. ترتيب التنفيذ المقترح بعد هذه المراجعة

1. **دفعة صدق الواجهة:** تصحيح تسميات اللوحة الرئيسية والمداخل التي تعد بـ3D و100 لغة وAI حي، ثم APK.
2. **قبول Android المتبقي:** لغة جهاز غير عربية، نص طويل، بطاقات التواصل، العدسة اللاتينية، وTTS.
3. **محتوى موثوق:** schema للحزم، استيراد/حذف/فحص، ثم مصادر قانونية ومراجعة قبل محتوى ديني واسع.
4. **عقد الخدمة أولاً:** اختر مسار الصوت/PDF أو LLM واحداً فقط، واتفق على الفوترة والحذف والحدود قبل النشر.
5. **عزل المنصات:** prototype للفقاعة native وprototype منفصل للـ3D؛ لا تُجمع المكتبات قبل نجاح كل APK منفصل.
6. **دفع وPRO أخيراً:** Play Billing + backend entitlement + تشغيل/إبطال وتجديد، ثم سياسة الخطط.
7. **فيديو وصوت مخصصان:** بعد اختيار مزود مرخص، ميزانية، طابور، مراجعة محتوى، حقوق، وموافقة الصوت.

## 7. قرارات مطلوبة من المالك قبل الخدمات المدفوعة

لا تحتاج الخطوات الثلاث الأولى إلى قرار مالي. لكن قبل تشغيل الصوت، PDF، LLM، فيديو، نسخ صوت، أو PRO، يجب حسم المسائل التالية كتابةً:

| القرار | الخيارات المطلوبة |
|---|---|
| ميزانية تجريبية شهرية | حد أعلى للصوت، التخزين، الترجمة السحابية، LLM، والفيديو. |
| سياسة الملفات | مدة الاحتفاظ، الحذف التلقائي، حذف يدوي، وأنواع الملفات المسموحة. |
| المحتوى الديني | مصادر موثقة، حق الاستعمال، مستوى الاقتباس، ومراجع ظاهرة داخل القارئ. |
| الفيديو | مزود، لغة، جودة، مدة، شخصية/صوت، مراجعة قبل النشر، وحقوق الأصول. |
| الصوت المخصص | نموذج موافقة، ملكية، حذف عينة، ومنع انتحال أصوات الغير. |
| PRO | المنتجات، الأسعار، ما يدخل مجاناً/مدفوعاً، وتفعيل Google Play Billing. |
