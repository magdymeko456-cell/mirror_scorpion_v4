## قواعد الإصلاح

يجب تنفيذ الإصلاحات على مراحل صغيرة: أولاً نثبت الترجمة والصوت والحفظ المحلي، ثم نضيف API للمحتوى والذكاء، ثم نختبر كل كرت، وبعد ذلك فقط ننتقل إلى ميزات تحتاج صلاحيات أصلية أو مزود دفع. لا يجوز تسمية محاكاة مؤقتة «تفعيلاً حقيقياً» في واجهة المستخدم.

## حدود يجب توضيحها للمستخدم

الترجمة النصية والصوتية يمكن تفعيلها فعلياً الآن عبر الخدمات الموجودة. أما الترجمة فوق تطبيقات التواصل فهي وظيفة نظام Android تتطلب إذن نافذة عائمة وبناءاً أصلياً مخصصاً؛ لذلك يمكن ضمان النسخة داخل التطبيق، بينما يحتاج الوضع فوق التطبيقات إلى إعداد Native/Dev Client واختبار على جهاز Android حقيقي. كما أن توليد سيناريو فيديو بالذكاء الاصطناعي ممكن عبر LLM، لكن إخراج ملف فيديو سينمائي كامل يحتاج خط إنتاج فيديو منفصلاً ولا ينبغي تزويره بعرض نصوص مشاهد فقط.

## ترتيب التنفيذ

1. إصلاح المايك والنسخ ودبوس الحوار باستخدام المسارات الحقيقية الموجودة.
2. بناء API قصص ومحتوى تنزيل حقيقي مع تخزين محلي.
3. ربط LLM للإلهام وإثراء القصص وتوليد السيناريو المنظم.
4. تحويل تنزيل حزم اللغات من شريط محاكاة إلى تنزيل وكتابة ملفات فعلية.
5. تحسين الفقاعة داخل التطبيق، ثم توثيق متطلبات الفقاعة فوق التطبيقات.
6. اختبار الكروت الستة وحفظ نقطة تفتيش قبل أي توسعة أخرى.

## النتيجة الأولية

المشروع ليس فارغاً: الترجمة النصية ورفع الصوت والتفريغ عبر الخادم والشطرنج المحلي هي أجزاء حقيقية. لكن القصص والتنزيل والذكاء الخاص بالإلهام والفقاعة فوق التطبيقات وتفعيل PRO ما زالت تحتاج عملاً حقيقياً، ولذلك لا يصح اعتبار النسخة الحالية مطابقة كاملة للوصف قبل إتمام هذه المراحل.
