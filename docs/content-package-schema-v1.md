# مواصفة حزم المحتوى المحلية v1

> **الحالة:** عقد تصميم قبل التنفيذ. لا يفرض التخزين الحالي هذه الحقول بعد؛ لا ينبغي اعتبار أي ملف JSON مستورد موثقاً أو دينياً موثوقاً لمجرد نجاح حفظه.

## الهدف والحدود

تسمح الحزمة بإدخال قصص أو اقتباسات أو بيانات لغة اختارها المستخدم صراحة. ولا تنفذ هذه المواصفة تنزيلاً خلفياً، أو مشاركة بيانات، أو ترخيصاً مدفوعاً. وهي تفصل بوضوح بين **حفظ ملف محلي** و**مصدر محتوى موثوق قابل للعرض**.

## الغلاف الإلزامي

| الحقل | النوع | قاعدة القبول |
|---|---|---|
| `packageId` | نص | معرّف lowercase من أحرف وأرقام وشرطات فقط، وفريد داخل مساحة التطبيق. |
| `version` | نص | إصدار SemVer مثل `1.0.0` لتحديد التحديث والتوافق. |
| `title` | نص | عنوان معروض للمستخدم، من 1 إلى 120 حرفاً. |
| `kind` | نص | أحد: `stories` أو `inspiration` أو `language-data`. |
| `sourceCitation` | كائن | مرجع ظاهر للمستخدم: اسم المصدر، رابط/معرّف ثابت، وتاريخ الوصول إن وجد. |
| `license` | كائن | نوع الاستخدام، صاحب الحق، الرابط أو النص، وأي شرط نسبة أو منع إعادة توزيع. |
| `integrity` | كائن | `algorithm` يساوي `sha256` و`contentHash` بصيغة SHA-256 lowercase بطول 64. |
| `createdAt` | نص | وقت ISO-8601 لإنشاء الحزمة. |
| `items` | قائمة | عناصر المحتوى؛ لا تقبل قائمة فارغة. |

لا تكون `sourceCitation` أو `license` فارغتين في حزمة يوسم محتواها بأنه ديني أو منقول. تبقى حزم المالك الأصلية موسومة صراحةً بـ`ownerProvided: true` ولا تنسب إلى مصدر ديني أو خارجي.

## مثال هيكلي

```json
{
  "packageId": "owner-inspiration-ar",
  "version": "1.0.0",
  "title": "إلهام مقدم من مالك التطبيق",
  "kind": "inspiration",
  "ownerProvided": true,
  "sourceCitation": {
    "name": "محتوى مقدم من مالك التطبيق",
    "reference": "owner-submission-2026-08-24"
  },
  "license": {
    "usage": "owner-authorized",
    "rightsHolder": "مالك التطبيق"
  },
  "integrity": {
    "algorithm": "sha256",
    "contentHash": "<sha256-of-canonical-content>"
  },
  "createdAt": "2026-08-24T00:00:00Z",
  "items": []
}
```

## قواعد الاستيراد والحذف

يجب أن يعرض الاستيراد قبل الحفظ: العنوان، النوع، المصدر، الترخيص، والإصدار. يتحقق التطبيق من البنية، ثم من الهاش على المحتوى المعياري قبل الكتابة الذرية. لا يستبدل إصدار أقدم إصداراً أحدث. ويحتاج كل سجل ظاهر إلى زر حذف صريح يمسح ملف الحزمة وحالة فهرستها، مع تأكيد للمستخدم. لا يرسل الملف إلى أي خادم.

## خطة التنفيذ والاختبار

تضيف الدفعة البرمجية التالية نموذج Dart للحزمة، وvalidator مع اختبارات قبول/رفض، وحساب SHA-256، وحفظاً ذرياً، وحذفاً من الواجهة. ويُختبر على Android: استيراد حزمة صحيحة، رفض نقص المصدر أو الترخيص أو الهاش، رفض هاش غير مطابق، ومنع downgrade، ثم حذف الحزمة واستعادة قائمة فارغة.

## مراجع المشروع

1. `lib/core/content/offline_content_storage.dart` — التخزين الحالي الذي يحتاج توسيعاً.
2. `assets/data/content_manifest.json` — فهرس الحزم المرفقة.
3. `docs/v4-full-requirements-acceptance-matrix.md` — قواعد المحتوى والقبول.
