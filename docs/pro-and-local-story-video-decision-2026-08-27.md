# قرار هندسي مبدئي: PRO وفيديو القصص المحلي

## النطاق والحالة

تعمل الترجمة النصية المحلية على Android، لكن ميكروفون الحوار ودبوس الملف الصوتي ما زالا تحت قبول Android منفصل. لذلك **لا يضيف هذا القرار أي قفل PRO ولا أي مكتبة فيديو ولا أي زر شراء أو تصدير**. الغرض هو منع بناء حماية ظاهرية تعتمد على ساعة الهاتف، أو دمج مكتبة فيديو متقاعدة، ثم ترتيب تجربة صغيرة قابلة للقياس والموافقة.

## عقد PRO: مقارنة البدائل

| العنصر | الخيار أ: Google Play + Firebase Functions | الخيار ب: RevenueCat |
|---|---|---|
| مصدر الحقيقة | Function مملوكة للتطبيق تتحقق من رمز شراء Play عبر Google Play Developer API وتحفظ حالة الاستحقاق | حالة استحقاق يديرها RevenueCat مع ربط المتجر |
| أحداث التجديد/الإلغاء/الاسترداد | RTDN إلى Cloud Pub/Sub، إزالة تكرار `messageId`، ثم استعلام API للحالة الكاملة | خدمة المزود تزامن أحداث المتاجر وتعرض الاستحقاق عبر SDK/API |
| حماية سلامة الاستجابة | استحقاق قصير العمر يوقّعه خادم التطبيق بمفتاح خاص، ويُتحقق منه في APK بمفتاح عام | Trusted Entitlements تفحص توقيع استجابة الاستحقاق، لكن قرار القبول أو الرفض يبقى في كود التطبيق |
| عبء التشغيل | أعلى: يلزم Function وتحقق API ومسار Pub/Sub ومراقبة الإبطال | أقل في منطق المتاجر، لكن يضيف مزوداً خارجياً وسياسة خدمة وتكلفة لاحقة |
| التوسع عبر منصات | يحتاج تطبيقاً موازياً لكل متجر | مناسب أكثر عند إضافة iOS أو web لاحقاً |
| القرار المبدئي | **المسار المرشح للنسخة Android الحالية** لأن Firebase موجود بالفعل ولا توجد مشتريات مفعلة | خيار مراجعة قبل توسع متعدد المنصات، لا اعتماد ولا مفتاح في هذه المرحلة |

توصي Google بأن يحدّث الخادم سجله عند إشعار RTDN، ثم يستدعي Google Play Developer API للحصول على حالة الشراء الكاملة؛ فالإشعار وحده لا يحمل المعلومات الكاملة.[1] [2] وتوضح RevenueCat أن تحقق التوقيع في Trusted Entitlements لا يحجب الوصول تلقائياً؛ بل يقدم نتيجة يجب أن يقرر التطبيق كيفية استعمالها.[3]

## عقد الاستحقاق المقترح

يحصل العميل، بعد تحقق خادمي ناجح فقط، على استحقاق موقّع يحوي `kid` و`entitlementId` و`productId` و`appInstanceIdHash` و`issuedAtServer` و`storeExpiresAt` و`offlineUntil` و`signature`. تكون `offlineUntil` أقل من أو تساوي نهاية المتجر، وتحددها سياسة قصيرة معلنة لاحقاً بعد اختبار الترميم دون اتصال. لا يحفظ التطبيق رمز شراء المتجر أو أي مفتاح خادم داخل APK.

يُنشأ `appInstanceId` عشوائياً ويحفظ في التخزين الداخلي أو يستند إلى Firebase Installation ID عند توفره، ثم يُرسل هاشه فقط مع طلب الاستحقاق. لا يستخدم التطبيق الرقم التسلسلي أو IMEI أو MAC. توصي Android باستخدام معرّف قابل لإعادة الضبط ومحدود النطاق مثل FID أو GUID لمعظم الحالات غير الإعلانية، وتقيّد الوصول إلى المعرّفات المادية غير القابلة لإعادة التعيين.[4]

> لا يمكن لوضع offline وحده أن يمنع كل عبث في جهاز يسيطر عليه المستخدم. ستستخدم النسخة المستقبلية آخر وقت خادمي موثوق لاكتشاف الرجوع الكبير في ساعة الجهاز، وفترة سماح محدودة، ثم تحقّقاً جديداً عند الاتصال. هذا تخفيف للمخاطر، لا ادعاء بحماية مطلقة.

## سياسة الوصول قبل التنفيذ

تظل Whisper والفيديو وخدمات النسخة المجانية غير مقفلة حتى تجتاز قبول Android الفعلي. عند اعتماد PRO لاحقاً، يكون القفل في طبقة خدمة مشتركة، لا في إخفاء زر فقط، ويعرض سبب الرفض وتاريخ آخر تحقق وفترة السماح من دون عرض رمز شراء أو بيانات حساسة. لا يضاف دفع أو اشتراك أو مفتاح أو خدمة خلفية في هذه الدفعة.

## فيديو القصص المحلي: مقارنة البدائل

| العنصر | الخيار أ: FFmpegKitNext مبني من المصدر | الخيار ب: Android MediaCodec/MediaMuxer عبر جسر Kotlin |
|---|---|---|
| حركة الصور وKen Burns | مرشحات FFmpeg مناسبة للـpan/zoom والانتقالات | تُرسم الإطارات في Canvas وتُشفّر محلياً؛ تحتاج عملاً أصلياً أكبر |
| الصوت والمؤثرات | خلط ومسارات وfade مرن | أبسط لمسار صوت واحد؛ خلط المؤثرات وترميزها يزيد تعقيد الجسر |
| التوزيع والبناء | لا توجد حزمة pub/Maven جاهزة في الاستمرار الرسمي؛ يلزم بناء مصنوعات Android من المصدر وCI منفصل | لا يضيف مكتبة FFmpeg، لكنه يعتمد codecs الجهاز وقد يختلف الدعم |
| الترخيص | LGPL افتراضياً عند تجنب `--enable-gpl`؛ اختيار المكتبات والـcodecs يحتاج سجل بناء وإفصاح ومراجعة قانونية | لا يعفي من مراجعة codec أو سياسات المتجر، لكنه لا يوزع FFmpeg |
| الحجم | يقاس بعد Prototype فقط؛ لا تقدير ثابت | غالباً أقل من مكتبة كاملة، لكن لا يدعم المرشحات المعقدة مجاناً |
| القرار المبدئي | **خيار تجربة لاحقة** فقط إذا تأكدت الحاجة إلى المؤثرات والخلط | خيار بديل لفيديو قصير بسيط بعد قياس التوافق والجودة |

أُعلن تقاعد FFmpegKit التاريخي، بينما يصف الاستمرار الرسمي FFmpegKitNext نفسه بأنه مصدر فقط يتطلب بناءً محلياً للمصنوعات المستهدفة؛ لذلك لا تضاف تبعية Flutter قديمة أو binary غير موثق.[5] [6] وتوضح وثائق FFmpeg أن تفعيل أجزاء GPL أو مكتبات إضافية يغير التزامات التوزيع، وأن اعتبارات codec والبراءات ليست موحّدة بين الولايات القضائية.[6]

## تجربة الفيديو الوحيدة المسموح بها لاحقاً

بعد قبول المايك ودبوس الصوت، تكون التجربة فيديو **20–30 ثانية** بدقة 720p من ثلاث صور أو رسوم مرخّصة، تعليق صوتي واحد يختاره المستخدم، انتقالات خفيفة، وحركة pan/zoom بطيئة. يعرض التطبيق قبل التنفيذ الحجم المتوقع للمخرجات والمساحة الحرة وتنبهاً للبطارية والحرارة، ولا يبدأ تنزيل أصول أو تصدير ملف إلا بعد اختيار وموافقة صريحة. لا يشمل النموذج الأول فيديو 5–15 دقيقة أو مؤثرات متعددة أو رفع قصة أو صوت إلى أي خادم.

## معايير قبل أي دمج

| المعيار | الشرط |
|---|---|
| المحتوى | مصدر وترخيص وإسناد لكل صورة ومؤثر وصوت؛ لا أصول من Chess Club أو أي تطبيق آخر |
| البناء | مشروع/CI منفصل لمكتبة الفيديو، وفحص حجم APK وABI ورخص البناء قبل دمجه في `main` |
| الخصوصية | اختيار وموافقة لكل ملف أو قصة، ومسح الملفات المؤقتة بعد النتيجة أو الإلغاء |
| الاستقرار | اختبار Android قصير للحرارة والمساحة والإلغاء والخلفية قبل توسيع المدة أو الدقة |
| PRO | لا قفل قبل اعتماد مسار استحقاق خادمي واختباره بالشراء والاسترداد والانتهاء وoffline |
